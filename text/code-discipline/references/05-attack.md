# 模式 5 — 对抗性测试

目标不是「证明它能用」，是**用最省力的方式把它弄坏**。

普通测试问「功能是否正常」，对抗测试问「什么样的输入或时序能让它交出错误答案」。两种测试的写法完全不同：前者构造合法输入，后者**主动构造违法输入**。

## 八类攻击面

逐类过。每类至少试 3 条，全过就记一行「已试，无效」——**灰名单比空白更可信**。

### 1. 输入畸形

| 攻击 | 期望的防御 |
| --- | --- |
| 类型错位：往需要 `list` 的地方给 `str`、`int`、`None` | 明确报错，不是默默 `for c in "abc"` 拆成字符 |
| 缺字段 / 多字段 | 缺字段给 400 且说明缺哪个；多字段忽略而不是崩 |
| 嵌套炸弹：`[[[[[...]]]]]` 或超大 JSON | 深度/大小上限，不是 RecursionError |
| 超长字符串（1MB 名字） | 长度上限，且截断不切断 UTF-8 字符 |
| 负数下标 / 越界下标 | IndexError 有上下文，或被钳制 |
| 特殊值字符串：`"null"`、`"undefined"`、`"NaN"`、`"None"` | 不被当成字面值存进库 |
| 同一字段重复出现（query 参数 / JSON 键） | 取第一个还是最后一个要确定，不能随机 |

### 2. 数值边界

| 攻击 | 期望的防御 |
| --- | --- |
| `0`、`-1`、`1e308`、`-0.0` | 不做除法、不当长度 |
| `NaN` / `Infinity` | 不被写进数据库，不参与比较（`NaN != NaN` 会让去重失效） |
| 整数溢出（`int` 上限、时间戳 `*1000`） | 用合适类型，或显式检查 |
| 精度：`0.1 + 0.2`、累加 10 万次 | 金额/计数要么整数分，要么 Decimal |
| 舍入：`2.675` 四舍五入 | `round()` 用银行家舍入，`round(2.675, 2) == 2.67`；业务要的通常是 `ROUND_HALF_UP` |
| 除零 | 返回 0 还是报错要确定，不能抛未捕获异常 |

### 3. 编码与文本

| 攻击 | 期望的防御 |
| --- | --- |
| emoji（`👨‍👩‍👧‍👦` 是 7 个 code point） | 按 grapheme 截断，不切出半个字符 |
| 组合字符（`é` vs `e` + 声调） | 比较/去重前归一化（NFKC） |
| 全角/半角（`Ａ` vs `A`、`１２３`） | 搜索和校验前统一 |
| 零宽字符、RTL 控制符 | 不被用于伪造文件名或绕过关键词过滤 |
| 大小写：`İ` `.lower()` 变成两个字符 | 不要在长度敏感处用 `lower()` |
| 换行注入：`\r\n` 进 Header / 日志 | 过滤 `\r\n`，否则日志伪造、响应头注入 |

### 4. 时间与时区

| 攻击 | 期望的防御 |
| --- | --- |
| 跨时区：`23:30` 本地 vs UTC | 存储层全 UTC，展示层转；比较前必须同 tz |
| DST 跳变：凌晨 2:30 不存在 / 出现两次 | 用 aware datetime，不做 naive 加减 |
| 闰秒 / 闰年 `2024-02-29` | 不做 `+ 365 天` 这种假设 |
| 时钟回拨（NTP 校正） | 依赖时间差的地方用单调时钟 `time.monotonic()` |
| 日期无时间：`2026-10-20` 解析成 00:00 还是当天结束 | 业务语义要明确，边界差一天 |
| 超远未来/过去：`9999-12-31`、`1970-01-01` | 数据库类型能装下，不能溢出 |

### 5. 并发与竞态

| 攻击 | 期望的防御 |
| --- | --- |
| 同一请求连发两次（双击、重试） | 幂等键或唯一索引，不产生两条 |
| 两个请求同时读-改-写同一行 | 行锁 / 乐观锁版本号，不丢更新 |
| 并发下计数器不准 | 原子操作或数据库自增，不用「读出来 +1 再写」 |
| 连接池耗尽（并发 100） | 有超时、有上限、耗尽时快速失败而不是挂死 |
| 死锁：两个事务反序加锁 | 固定加锁顺序，或捕获死锁重试 |
| 缓存击穿（缓存过期瞬间 1000 并发打 DB） | 单飞 / 互斥锁 |
| 顺序依赖：A 还没提交，B 就读 | 明确隔离级别，不假设「刚才写的一定读得到」 |

### 6. 网络与外部依赖

| 攻击 | 期望的防御 |
| --- | --- |
| 超时（连接超时 / 读超时分开） | 两个都要设，且不能是默认的「永不超时」 |
| 5xx / 429 | 有重试且**带退避**，不是立即重试；只重试幂等请求 |
| 半包 / 响应被截断 | 解析失败要报错，不能返回半个对象 |
| 返回结构变了（字段变 null / 少字段 / 类型变） | 容错或明确失败，不做 `resp["data"]["id"]` 裸取 |
| 302 重定向到恶意地址 | 不盲目跟随，尤其带鉴权头时 |
| DNS 失败 / 连接被 RST | 快速失败，不无限重试 |
| 慢响应（30 秒才回） | 有超时；不阻塞主线程 |
| 证书过期 | 不 `verify=False` 绕过 |

### 7. 资源与容量

| 攻击 | 期望的防御 |
| --- | --- |
| 一次查 10 万行 | 分页/游标，有硬上限 |
| 内存里攒大 list | 流式处理或分批 |
| 文件句柄 / 连接不关 | `with`、`finally`、连接池归还 |
| 磁盘写满 / 临时目录不存在 | 写失败要报出来，不吞 |
| 无界队列 / 无界缓存 | 有上限 + 淘汰策略 |
| 循环里发 IO（N+1） | 批量取，见模式 6 |

### 8. 错误假设

这一类最难测，因为要攻击的是**需求里没说出口的前提**。

| 攻击 | 期望的防御 |
| --- | --- |
| 假设列表顺序稳定（`sort` 不稳定、`set` 无序） | 显式排序；多键排序要加 tie-breaker |
| 假设字典键顺序 | Python 3.7+ 有序，但 JSON 反序列化后不一定 |
| 假设「记录一定存在」 | 先查再删、`get_or_create` 的竞态 |
| 假设「金额一定是正数」 | 退款就是负数 |
| 假设「一个用户只有一条记录」 | 唯一约束真的建了吗 |
| 假设分页时数据不变 | 边翻页边插入导致重复/遗漏 |
| 假设时区是本地 | 服务器是 UTC |
| 假设请求体一定是 JSON | 可能是 form、可能是空 body |
| 假设鉴权在网关做了 | 内网直连时没人鉴权 |

## 分诊

每个发现的问题落进三个桶之一，**不许「都修」或「都不修」**：

| 桶 | 判据 | 处理 |
| --- | --- | --- |
| **真问题** | 能构造出真实触发路径，后果是错误数据/崩溃/越权/泄露 | 写测试 → 修 → 测试留下 |
| **已知限制** | 触发条件真实但极不可能，或修复成本远大于风险 | 写进文档/注释，加监控告警，汇报里明说 |
| **不修** | 触发路径不存在（前提条件在当前系统里不可能成立） | 汇报里给理由，一句话 |

「不修」不等于「没发现」。**最差的做法是发现了但不说，或者说了但不给判断。**

## 修复顺序

对每个真问题：

1. 先用**模式 3** 的方式写一个失败的测试（证明这个问题真的存在）。
2. 最小改动修（模式 2）。
3. 测试变绿。
4. **这个测试永久留下**。它现在是回归测试，不是临时脚本。

顺序不能倒。先修后补测试，补出来的测试会迁就修复后的行为，测不出「不修会怎样」。

## 不要攻击的东西

- 第三方库内部的实现（不是你的代码，改了也会被覆盖）
- 框架已经处理好的部分（Flask 的请求解析、Django 的 ORM 转义）——除非你怀疑用法错了
- 性能压测（除非用户给了明确指标；对抗测试关心的是「坏掉」，不是「慢多少」）
- 纯展示层的像素级差异

## 汇报格式

```
攻击面：8 类 / 34 条；有效攻击 4 条
真问题 3：
  - 超长名字（>64 字符）截断切断了 emoji，库里存了半个字符 → 已修 + 回归测试
  - 同一请求连发两次产生 2 条订单 → 已加幂等键 + 回归测试
  - 5xx 重试无退避，重试 3 次放大成 9 次请求 → 已改为指数退避
已知限制 1：
  - 并发 100 时连接池耗尽返回 500 而非 503（无监控，先记录）
不修 2：
  - 数值溢出：输入上限由网关控制在 2^31 内，进程内不可能溢出
  - DST 跳变：全站 UTC 存储，不涉及本地时间运算
```

## 反模式

- **只测「输入为空」就收工**。空输入是最容易想到也最不常发生的。真实故障更多来自**半合法输入**（格式对、语义错）。
- **把断言写成「不抛异常就算过」**。崩掉才是好事，算错但没崩才是灾难。
- **发现 10 个问题全标成「低优先级」**。这是在保护自己的工作量，不是在保护系统。
- **修完不补测试**，理由「这个场景不会再有了」。攻击本来就是找「想不到的场景」。
- **只测自己写的那几行**。新代码的问题常常在和旧代码的接缝处。
