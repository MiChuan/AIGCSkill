# 去水印与 8K：原理、参数、局限

## 一、水印从哪来

Hy Image3.5 的 API 里有个 `footnote` 字段，作用是**自定义水印文字**（≤16 字，右下角）。

所以处理顺序是：

1. **不请求**——`footnote` 不传，就没有平台水印。这一步挡掉 90% 的情况。
2. **检测 + 补片**——部分接入方（含某些渠道）会在成图上叠自己的标，这时靠 `finalize.py --watermark auto`。
3. **手动指定**——水印位置固定且规律时，`--watermark box:x,y,w,h` 最稳。

提示词里写"不要水印"只能减少模型自己画的签名字样，**管不到后处理叠加的 logo**，别指望它。

## 二、检测算法（`detect`）

右下角取一个 25%×14% 的窗口，切成 12×5 块，算每块的边缘能量（`FIND_EDGES` 后取均值）：

- 水印是文字/logo，笔画边缘的能量远高于同窗口的天空、云、墙面渐变。
- 取**中位数**做基线（中位数不被少量高能量块拉高），阈值 = max(中位数×2.2, 8.0)。
- 超过阈值的块连成的区域就是候选；分数 = 热块占比 × 2.4。
- 候选框会**贴到右下角**再补片——水印永远贴角，宁可多补一圈，也别留下半个字。

`score ≥ 0.30` 才判定有水印。低于阈值不补片（避免把干净画面糊一块）。

已知漏检：**浅色背景上的淡水印**（白字压白云）。这种情况下分数会很低，需要人眼确认后手动 `box:`。

## 三、补片算法（`patch`）

不是智能修复（inpaint 需要模型），是**同高度镜像取源 + 配色对齐 + 羽化融合**：

1. 从目标框左侧等宽区域取一块，水平镜像，保证纹理方向不突兀。
2. **配色对齐**：把补片三通道均值平移到目标框四周 8px 边带的均值（系数 0.85，留一点差异更自然）。
3. **掩膜**：内部大面积实心，只在边缘留一圈羽化带——羽化带太宽会让水印从半透处透出来，这是最常见的翻车点。
4. 最后对补片区做 0.9px 高斯，压掉镜像纹理与周围的接缝。

适用：天空、云、雾、墙面、水面、虚化背景。
**不适用**：穿过水印的硬结构（栏杆、山脊线、人物衣角）——补完会断线。这种情况要么重出图，要么手修。

## 四、8K 的真相

| 环节 | 数值 |
| --- | --- |
| 模型原生 | 宣传 2K；API 传 size 可到 4096×4096、单边 8192（总面积 ≤ 16,777,216 px） |
| 交付 8K（16:9） | 7680×4320 |
| 倍率 | 2048→7680 = 3.75× |

**放大不增加信息量**。`finalize.py` 做的是：分级 2× Lanczos 放大（避免一次大倍率放大糊成一团）→ 终尺寸 Lanczos → `UnsharpMask`（radius 随倍率在 1.2–3.6 之间，percent 85，threshold 3）。

所以 8K 的真实价值是：

- 满足平台/印刷的**尺寸**要求
- 在 100% 查看时边线依然锐利，不像直接拉伸那样软

**不是**：真有 8K 的细节。要印刷级细节，得接超分模型（Real-ESRGAN 之类）或分段重绘。

如果用户问"是不是真 8K"，就照上面这段回答。

## 五、参数

```
--target {native,2k,4k,8k}     长边目标：2048 / 3840 / 7680
--watermark {auto|off|box:x,y,w,h}
--force-region                 检测不到也强行补右下角默认窗口
--format {jpg,png,webp}        默认跟随输出扩展名
--quality 95                   jpg/webp 质量
```

建议：

- 交付用 `jpg --quality 95`（8K 的 PNG 通常 20–40MB，没必要）
- 需要再加工（二次调色、印刷）用 `png`
- 先 `--target native` 看补片有没有翻车，再出 8K——别在 8K 上试错
