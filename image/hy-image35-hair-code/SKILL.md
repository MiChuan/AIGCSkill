# 发型代码：先算代码，再出试发图

一句话：**把「你适合什么发型」从一道审美题，变成先测量、再查表、最后画到你脸上的三步。**

用户真正想要的是「我该剪什么」，不是「有哪些发型」。所以这个 skill 有一半的篇幅在讲怎么判断题，只有一半在讲怎么出图。

## 和原图的关系

参考图那张「你的代码 + 你的发质」九宫格是**审美稿**，不是诊断表：

- 它的九行款式表（9 组 × 3 发质 = 27 组）很好用，本 skill 全部保留，一款不改；
- 但它的代码有裂缝：**第三位九行恒为 A**（`AAA ABA ACA / BAA BBA BCA / CAA CBA CCA`），真正变化的只有前两位；「面部特点」列每行都复制了「长脸」，和「组别」列的分组自相矛盾；第三位的用词在三组之间漂移（额头宽 / 额骨宽 / 颧下颔宽）。
- 所以本 skill 把代码拆成三位各管一件事：**脸型 / 最宽处 / 指宽**。九行款式按前两位索引，第三位只改刘海露额度与顶部体积。原图代码保留在 `data/hair-matrix.json` 的 `alias` 里，输出时会同时打印「代码 BBB（原图对应 BBA）」，对照不会错位。

拆开的好处：27 种组合都有解（原图只有 9 种，「三指 + 方脸」这类现实里存在的组合在原图里根本没有格子），而且第三位真的有内容。细节见 `references/code-system.md`。

## 四条不可让的约束

### 1. 先诊断，再推荐

**不许跳过测量直接给款式。**跳过这一步，这个 skill 就退化成一张网红发型清单，和原图没有区别——而用户要的恰恰是「为什么是我」。

代码必须由数字推出来，每一步判据都打印出来（`--json` 可存档）。用户不认这个结论时，能看到是哪一步岔开的，而不是一句「AI 觉得你适合」。

### 2. 发质和脸型同级，不是补充信息

同一个「自然中分、轻层次中长」：细软发是贴着头皮的一片，硬直发是两侧支棱的一片，自然卷是蓬成三角的一片。

款式没错，错在没人问过头发答不答应。所以发质是代码之外的一整个维度（A 细软 / B 硬直 / C 自然卷），直接决定查表取哪一列，也决定提示词里能不能写「蓬松」「空气感」这类词。

### 3. 只换头发 = 四把锁

| 锁 | 锁不住会怎样 |
| --- | --- |
| 身份（脸型骨相、五官、肤色） | 换出来是另一个人，不是同一个人的新发型 |
| **发际线**（高度、形状、额角、鬓角起点、发旋） | 三庭比例变了，脸型跟着变——这是最隐蔽也最致命的一条 |
| 光（光位、光比、色温） | 头发的体积是靠光读出来的，光一变，同一个发型看起来就是两个发型 |
| 背景 + 构图 + 衣物 + 表情 | 三张方案没法并排比较：你不知道自己喜欢的是发型，还是那张图的氛围 |

发际线单独列一锁，是因为它最容易被忽略、又最容易被观众一眼看出。细节见 `references/prompt-formula.md`。

### 4. 一张图只换一个变量

三款方案 = 三次生成，同一张参考图、同一段「保持不变」，只换【目标发型】。

一次生成里要三个发型，得到的是三张脸或者一个半中分半狼尾的东西。

## 代码体系

| 位 | 含义 | A | B | C |
| --- | --- | --- | --- | --- |
| 1 | 脸型 | 长脸（长宽比 ≥ 1.55） | 方脸（< 1.55 且 下颌/颧 ≥ 0.86） | 宽脸（< 1.55 且 下颌/颧 < 0.86） |
| 2 | 最宽处 | 额部（太阳穴） | 颧骨（颧弓最外点） | 下颌（下颌角） |
| 3 | 指宽 | 三指（约 6.0–7.5cm） | 四指（7.5–9.6cm） | 五指（9.6cm 以上） |

`BBB` = 方脸 · 颧骨最宽 · 四指额头。测量方法、边界、并列判定、以及「原图哪里不自洽」全在 `references/code-system.md`。

## 流水线

### Step 0 — 收料

按顺序问清楚，缺一项都会返工：

1. **正脸照**（放 `assets/face.jpg` 或给路径）：不戴帽、刘海拨开、光从左前方来、不仰头不低头。
2. **发质自述**：一句话就够——「洗完头不吹，半小时后是趴着还是蓬着」。这句比看照片准。
3. **底线**：不能接受的长度、不接受的分缝、能不能推两侧。这一条会砍掉一半款式，早问省一轮。
4. **性别/发长**：表里的 27 款是**男发**（中短发为主）。女性/长发请走下面「非男发怎么办」。

出图消耗积分（一张约 5–10 积分），开跑前说明。

### Step 1 — 诊断

```bash
# 打网格，读六个位置（发际线/眉心/下巴的 y，额/颧/下颌的 x 跨度）
python scripts/haircode.py --guide assets/face.jpg --out out/guide.png

# 喂回去：直接得到代码 + 处方 + 查表推荐
python scripts/haircode.py --forehead 210 --face-length 620 \
    --temple 470 --cheek 520 --jaw 470 --unit px --hair fine
```

也可以跳过测量，直接给结论（用户自己已经知道脸型时）：

```bash
python scripts/haircode.py --shape square --widest cheek --fingers 4 --hair hard
```

输出四块：**怎么判出来的**（每个量的比值与判据）、**处方**（脸型/最宽处/指宽/发质各一条，带「为什么」）、**推荐**（查表得的 2–4 款，每款六个结构参数 + 为什么 + 注意）、**避雷**（这一组不能做的）。

质量门会提示：三个宽度并列（`H601`）、五指额头撞上露额款（`H602`）、三指额头配压眉刘海（`H603`）、像素换算假设（`H604`）、款式在发质黑名单里（`H605`）、细软配中长发（`H606`）、自然卷配齐刘海（`H607`）。

### Step 2 — 定方案

把推荐的 2–4 款连同「为什么」讲给用户，让他选 2–3 款试。**不要替他选**——试发的意义就在于让他看见差别。

用户不喜欢推荐里的任何一款时，可以从表里自选（`--emit-spec --style N` 只覆盖推荐列表；自选款手写 spec 会触发装配器的 `W603` 提示，结构照自己写的走，但先确认不撞发质黑名单）。

### Step 3 — 装配提示词

```bash
python scripts/haircode.py --shape square --widest cheek --fingers 4 --hair hard \
    --emit-spec --style 1 --ref assets/face.jpg --out-spec specs/s1.json
python scripts/build_hair_prompt.py --spec specs/s1.json --outdir out/s1
```

产出 `prompt.txt`（八段）+ `negative.txt` + `meta.json`。

**质量门会拦**：代码非法（E601/E602）、发质非法（E603）、结构六项缺项（E604）、长度写了「适中/稍长」这类模糊词（E605）、没锁发际线（E606）、没锁光/背景/构图（E607）、没有参考图（E608）。

只要有一条 error，就别出图。

### Step 4 — 出图

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `prompt` | `prompt.txt` 全文 | |
| `image1` | 参考照片 | 身份/光/背景/构图/衣物的唯一来源 |
| `input_fidelity` | `high` | 保脸开关，调低前面全白写 |
| `revise` | `false` | 开着会改写「发际线不动」「只改头发」 |
| `footnote` | 不传 | 这个字段本身就是水印文本 |
| `size` | `1536x2048`（3:4），或 `1600x2000`（4:5） | |
| `quality` | `high` | |
| `output_dir` | `out/<session>/raw` | |

每款一张。要判断层次，再加一张 45 度侧脸（同一个 spec，只改构图说明）。

### Step 5 — 对比 + 验收

```bash
python scripts/contact_sheet.py --ref assets/face.jpg \
    --img out/s1/raw/1.png out/s2/raw/1.png out/s3/raw/1.png \
    --labels "参考/现状" "1 自然中分" "2 轻层次中长" "3 三七分" \
    --crop head --out out/sheet.jpg
```

`--crop head` 把三张裁到同一个头肩比例。不裁的话，谁的脸占画面更大，谁看起来就更「适合」某些款式——那是构图在骗人。

**验收**（逐张过，任一条不过就重出，不要靠后期修）：

人
- [ ] 并排能一眼认出是同一个人，不是「同类型的人」
- [ ] 发际线位置、形状、额角、鬓角起点与参考图一致
- [ ] 皮肤纹理还在，没有磨皮、没有变年轻/变网红

发
- [ ] 六个结构参数图上都能对上：分缝在哪、刘海到哪、两侧到哪、后颈到哪、层次高低、体积方向
- [ ] 发质是对的：细软发根立起、发束成组；硬直有直线感、发尾带碎口；自然卷卷径不一、发尾外翘
- [ ] 发丝是一束一束的，不是一整块色块；边缘有少量飞散碎发，发际线处有绒毛不是刀切边

图
- [ ] 光位、背景、构图、表情、衣物与参考图一致
- [ ] 无水印、无文字、无 logo
- [ ] 三张之间只有发型不同

## 非男发怎么办

表里 27 款是男发（法式短发、侧背、狼尾、碎盖为主）。女性或长发用户，**不要生搬这些款式名**，而要拿同一条链路的产物：处方。

处方里的四条判断是全性别的：

- **露额度**：上庭长就遮 1/3–1/2，上庭短就保留碎口；
- **长度落点**：最宽处是颧骨，长度就别停在颧弓；最宽处是下颌，长度就明确过颌；
- **两侧**：颧宽用鬓角/侧发遮最外点，宽脸收两侧、方脸柔化轮廓；
- **顶部体积**：长脸压平、宽脸加高、方脸变圆。

款式从长发/中长发里按这四条去挑，结构六参数照 `references/hair-structure.md` 写。表只解决「男发有哪些现成款」，处方解决「为什么」。

## 常见误用

- **拿精修图当参考照**。重度美颜会把皮肤纹理、脸型边缘一起锁进结果，出来是「精修过的你」，不是「剪了头发的你」。
- **用侧脸照诊断**。侧脸量不到额宽和颧宽，代码必错。
- **一次生成要三款**。见约束 4。
- **把三张图拼在一起就以为在对比**。没统一裁切比例的拼图，比的是脸的大小。
- **忘了问发质**。脸型判错最多是不太适合，发质判错会让头发不像头发——观众一眼看出是生成的。
