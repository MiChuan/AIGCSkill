# 代码体系：三位数字怎么来

一句话：**这个 skill 的推荐之所以能复现，是因为「你是谁」被压成了三个可测的数——脸型、最宽处、指宽。**

原图那张九宫格好看，但它不是诊断表：同一个「三指 + 长脸 + 额头宽」既可以配法式短发，也可以配三七分，靠的是设计师的眼睛。眼睛不可复现，所以我们先把它拆成能测的量，再去查它给的那 27 组款式。

---

## 一、三位代码

| 位 | 含义 | A | B | C |
| --- | --- | --- | --- | --- |
| 1 | 脸型 | 长脸 | 方脸 | 宽脸（圆脸 / 短宽脸） |
| 2 | 最宽处 | 额部 | 颧骨 | 下颌 |
| 3 | 指宽 | 三指 | 四指 | 五指 |

`ABB` = 长脸 · 颧骨最宽 · 四指额头。

款式表按**前两位**索引（3 × 3 = 9 行，正好对应原图九行），第三位只改两件事：刘海露多少额、顶部要不要加高。原因见下面第四节。

---

## 二、三个量怎么测

### 1. 指宽（额头高度）

**手指横量法**（原图用的就是这套，也是理发店的常用手势）：食指、中指、无名指并拢，横放在眉心和发际线正中最高点之间。

| 指宽 | 高度 | 含义 |
| --- | --- | --- |
| 三指 | 约 6.0–7.5cm | 上庭偏短 |
| 四指 | 约 7.5–9.6cm | 标准 |
| 五指 | 约 9.6cm 以上 | 上庭偏长 |

判定：`指宽数 = 额头高度 ÷ 2.2cm`，四舍五入到 3/4/5。`2.2cm` 是成年人食指—无名指并拢的常见宽度，可以用 `--finger-width` 改成你自己的。

**为什么不用「额头看起来高不高」**：绝对高度没有意义。脸长 17cm 的人，7cm 的额头是「五指」；脸长 22cm 的人，7cm 是「三指」。指宽本身就是一把以脸为单位的尺子，所以它稳定。

**比例校验**：`额头高度 ÷ 脸长`，0.33 是三庭等分的基准线。低于 0.33 偏短，高于 0.40 偏长。两个口径差得远时（比如指宽算出来是四指、比例算出来是五指），按比例走——手指的宽度个体差异比脸长的差异大。

### 2. 脸型

用两个比值，不用「看轮廓圆不圆」：

```
长宽比   = 脸长（发际线中点到下巴最低点） ÷ 脸宽（三者最大者）
下颌比   = 下颌宽 ÷ 颧宽
```

| 脸型 | 判据 |
| --- | --- |
| A 长脸 | 长宽比 ≥ 1.55 |
| B 方脸 | 长宽比 < 1.55，且 下颌比 ≥ 0.86（下颌角方，下颌与颧骨差不多同宽） |
| C 宽脸 | 长宽比 < 1.55，且 下颌比 < 0.86（轮廓收得快，下颌角不突出） |

**为什么不看轮廓**：轮廓是软组织，笑与不笑、胖五斤瘦五斤都会变；骨骼的比值稳定得多。而且「方」和「圆」在照片里最容易被镜头畸变和发型遮挡骗过去——颧骨两侧留一撮头发，圆脸也能拍出方脸。

### 3. 最宽处

| 代号 | 位置 | 取点 |
| --- | --- | --- |
| A 额部 | 上庭 | 两侧太阳穴最凹处 |
| B 颧骨 | 中庭 | 颧弓最外点 |
| C 下颌 | 下庭 | 下颌角最外点 |

取最大者。**差 1.5% 以内算并列**——照片的透视、镜头畸变、发型遮挡都能造成 1–2% 的误差，低于这个量的差别不可信，脚本会提示并列并给出两个候选列。

最宽处是三个量里最影响款式的一个：它决定视觉重心在哪一庭，也就决定「头发该往哪加、该在哪停」。

## 三、测量怎么落地（照片 → 数字）

不需要人脸关键点检测，也不需要装 mediapipe。流程是两步：

```bash
# 1) 打网格：照片上每 5% 一条线，坐标直接读得出来
python scripts/haircode.py --guide assets/face.jpg --out out/guide.png

# 2) 把读到的百分比喂回去（只用单位一致，脚本只算比例）
python scripts/haircode.py --forehead 210 --face-length 620 \
    --temple 470 --cheek 520 --jaw 470 --unit px --hair fine
```

读六个位置：

1. 发际线中点 y
2. 眉心 y（不是眉尾）
3. 下巴最低点 y
4. 额宽 x 跨度（太阳穴最凹处）
5. 颧宽 x 跨度（颧弓最外点）
6. 下颌宽 x 跨度（下颌角最外点）

**拍摄要求**（不满足就重新拍，别硬测）：

- 正脸，头部不仰不俯（仰头会让下颌宽虚高，低头会让额头虚高）
- 焦距别太短（手机前置广角会把鼻子放大、脸两侧拉窄），能拍到整张脸再加一点边距
- 不戴帽子、刘海拨开，露出真实发际线
- 光从左前方来，不要从正上方或正下方打——投影会盖住下颌角

`--unit px` 下判指宽要用一个假设：脸长 = 18.5cm（`--face-length-cm` 可改）。这个假设只影响「几指」，不影响脸型和最宽处。脸明显偏大偏小的照片，直接用厘米量更准。

## 四、原图的三处不自洽（照抄会出错）

这不是挑刺，是把原图当设计稿读——它是先有审美、后套公式的，所以公式有裂缝：

### 1. 「面部特点」列每行都写「长脸」

九行的第二列全是「三指/四指/五指 + **长脸** + 额头宽/颧骨宽/下颌宽」。但「组别」列把它们分成了长脸（AAA/ABA/ACA）、方脸（BAA/BBA/BCA）、五指偏宽型（CAA/CBA/CCA）。

第二列是模板复制出来的，**不能当判据**；真实的脸型分组看「组别」列。

### 2. 第三位九行恒为 A

`AAA ABA ACA / BAA BBA BCA / CAA CBA CCA` —— 全部以 A 结尾。也就是说在原图的编码里，第三位没有承担任何变量，真正变化的只有前两位（正好 3 × 3 = 9 行）。

### 3. 第三位的用词在漂移

同一行位里出现过「额头宽」「额骨宽」「颧下颔宽」三种写法，其中「额骨」不是标准解剖词。

**本 skill 的处理**：把它拆成 脸型 / 最宽处 / 指宽 三位各管一件事，九行款式按前两位索引，第三位只改刘海露额度与顶部体积。原图的九行代码完整保留在 `data/hair-matrix.json` 的 `alias` 字段里（`--json` 输出会同时打印「代码 AAA / 原图对应 AAA」），对照时不会错位。

顺带说：原图只有 9 种组合，但「三指 + 方脸」「五指 + 长脸」这些组合现实里都存在。拆开之后 27 种组合都有解，而且第三位真有内容——不再是个占位的 A。

## 五、判据冲突时按什么顺序信

1. **先信骨骼比值**（长宽比、下颌比、三个宽度），它们受拍摄影响最小。
2. **再信指宽**（受手指宽度个体差异影响）。
3. **最后信肉眼印象**（轮廓圆不圆、脸显不显宽）。

三条打架时，脚本会把判据原样打印出来，你自己能看到是哪一步岔开的。比如「长宽比 1.58 判长脸，但肉眼觉得很方」——大概率是下颌角被头发挡住，量错了下颌宽，重新拍一张空出鬓角的照片比争论更有用。

## 六、不要做的事

- **不要跳过测量直接给款式**。跳过这一步，这个 skill 就退化成一张网红发型清单，和原图没有区别。
- **不要用「脸型检测 App」的数字当结论**。那些算法大多只给一个「脸型标签」，不给你颧宽/下颌宽的原始比值，无法交叉验证，也无法判断它错在哪。
- **不要为了凑出某个代码去改测量值**。想要某款发型就直接说，脚本支持 `--shape/--widest/--fingers` 手动指定，比篡改数字诚实。
