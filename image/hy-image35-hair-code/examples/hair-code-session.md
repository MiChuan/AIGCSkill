# 一次完整会话：从一张自拍到三张试发图

这不是演示稿，是按流水线真跑一遍的记录。命令和输出都是脚本原样给的，可以照着复现。

需求原话：

> 我想换发型，但不知道自己适合什么。别给我网红款，先告诉我我是什么类型。

---

## Step 0 — 收料

三件事，缺一件后面都得返工：

| 要什么 | 为什么 |
| --- | --- |
| 一张正脸照（不戴帽、刘海拨开、光从左前方来） | 要量发际线、颧宽、下颌宽，任何遮挡都会让数字错位 |
| 发质自述 | 照片看不出支撑力，问一句「洗完不吹，半小时后趴着还是蓬着」最准 |
| 现在的发型 / 不能接受的长度 | 「不能剪短」会直接砍掉一半款式，早说省一轮 |

本例输入：

- 照片：正脸、无遮挡，光从左上 45 度
- 发质：细软（「洗完不吹就贴头皮」）
- 底线：两侧不要推光

---

## Step 1 — 诊断

```bash
python scripts/haircode.py --guide assets/face.jpg --out out/guide.png
```

网格图上读出六个位置（百分比），再喂回去：

```bash
python scripts/haircode.py --forehead 210 --face-length 620 \
    --temple 470 --cheek 520 --jaw 470 --unit px --hair fine
```

输出（节选）：

```
代码 BBA    原图对应 BBA    方脸 · 颧骨最宽
发质 A 细软

【怎么判出来的】
  脸型   方脸      脸长/脸宽 = 1.19（不到 1.55），且下颌宽/颧宽 = 0.91 ≥ 0.86，下颌角方、下颌与颧骨差不多同宽
  最宽处 颧骨最宽  额部 14.6、颧骨 15.6、下颌 14.2，最大的是颧骨
  指宽   三指额头  7.2cm ÷ 2.2cm = 3.27 指，不到 3.5 指

【处方】
  脸型｜方脸      纵向拉长、轮廓变圆：长度要么明显过颌，要么在上方做碎，任何横平竖直的线都要打断。
  最宽处｜颧骨最宽 中庭最宽：用纵向分线把颧宽切开，鬓角或侧发要遮住颧弓最外点；长度不要正好停在颧骨。
  指宽｜三指额头   上庭偏短：刘海可以遮，但不要压到眉下；露额时保留碎口，别整块露出。
  发质｜细软      细软发的敌人是长度和重量：越长，重量越往下拉，顶部越塌。
```

这一屏就是「你为什么适合这些」的全部依据。`--json` 存下来，回头对比另一次测量时能直接 diff。

**注意那两条提示**：

- `H606 细软发配中长/长发，重量会压在头顶上`——因为表里给 BBB（原图 BBA）开的是「自然中分、轻层次中长」，中长对细软发是个风险项。处理方式不是换款，而是在出图时把「发根立起」写死。
- 如果量出来三个宽度差不到 1.5%，会出 `H601` 并列提示——这种时候两个相邻列的款式都可以试，别硬选一个。

## Step 2 — 推荐

```
【推荐：查表得 2 款】

  [1] 自然中分
      分缝：自然中分，分线浅、两侧立起 1cm
      刘海：中分两侧到颧骨，发尾碎
      两侧：两侧盖耳，鬓角到颌角上缘
      后颈：后颈留到颈中
      层次：轻层次，中长，发尾柔
      体积：顶部自然，后脑饱满

  [2] 轻层次中长
      分缝：自然中分或轻侧分
      刘海：中分两侧长度到颧骨，向后梳一点
      两侧：两侧盖耳，鬓角到颌角上缘
      后颈：后颈留到颈中
      层次：轻层次：发尾齐而柔，重量均匀
```

为什么是这两款，而不是表里同样在这格的其他款？

- **方脸**要纵向拉长，**颧宽**要纵向分线切开——中分是唯一同时满足这两条的：它既是纵向线，又把长度拉到颌线以下。
- **细软**撑不住厚重，所以层次写「轻」，体积写「顶部自然」而不是「顶部饱满」——后者细软发做不出来。
- **两侧不要推光**这条底线，正好和「颧宽要鬓角遮颧弓」一致，没冲突。

如果这一格的推荐里有你不喜欢的（比如不接受中分），直接说。`--shape/--widest/--fingers` 支持手动指定，或者从表里另选一款走 `--style`——自选款会触发 `W603` 提示（不在推荐列表里），结构照你自己写的走，但先确认不撞发质黑名单。

## Step 3 — 出图

```bash
# 第 1 款
python scripts/haircode.py --shape square --widest cheek --fingers 3 --hair fine \
    --emit-spec --style 1 --ref assets/face.jpg --out-spec specs/s1.json
python scripts/build_hair_prompt.py --spec specs/s1.json --outdir out/s1
```

`build_hair_prompt.py` 会打印装配结果和质量门结论：

```
代码 BBA  发质 A  款式 自然中分  画幅 3:4 1536x2048
prompt: 1459 chars, 8 段；negative: 34 词
written: out/s1/prompt.txt, negative.txt, meta.json
```

没有 error 才出图。参数照 `meta.json` 里的 `imagegen` 段给：`input_fidelity=high`、`revise=false`、`footnote` 不传。

第 2 款重复一遍，只换 `--style 2` 和 `--out-spec`。

出图前说明一句：**一张约 5–10 积分，三款就是三张的消耗。**

## Step 4 — 对比

```bash
python scripts/contact_sheet.py --ref assets/face.jpg \
    --img out/s1/raw/1.png out/s2/raw/1.png \
    --labels "参考/现状" "1 自然中分" "2 轻层次中长" \
    --crop head --out out/sheet.jpg
```

`--crop head` 把三张裁到同一个头肩比例——不裁的话，谁的脸占画面更大，谁看起来就更「适合」某些款式，那是构图在骗你。

## Step 5 — 验收

三张图逐张过这五条，任一条不过就重出，不要靠后期修：

- [ ] 并排能一眼认出是同一个人（不是「同类型」）
- [ ] 发际线位置、形状、额角、鬓角起点与参考图一致
- [ ] 光位、背景、构图、表情、衣物没变
- [ ] 六个结构参数在图上能对得上（分缝在哪、刘海到哪、两侧到哪、后颈到哪）
- [ ] 发质是对的：细软发根立起、发束成组，不是一片厚毛

## 两个常见追问

**「能不能顺便染个色？」**

能，但要另开一次生成。染色会改变头发的明度关系（同一款发型，深色显厚、浅色显薄），和「只换形状」是两个变量。混在一次里，出来不对你分不清是形状的问题还是颜色的问题。

**「能不能烫？」**

烫本质上是换发质。「硬直烫卷」等于从 B 列跳到 C 列，表里的款式要重查一遍——发质一变，推荐的款式集合就变了。这不是加一句「烫一下」，是重新诊断。

## 一个踩过的坑

第一版做完 `haircode.py`，三款推荐的「结构」是同一份——因为结构写在 cell 上（一格一份），三款共用。

结果是：三款名字不同、三张图一模一样。对比图拼出来像三张复制品，用户会以为模型没听懂。

现在 `data/hair-matrix.json` 里多了 `overrides`：每一款只覆盖它真正不同的那几项（大多是一到三项），其余继承 cell 的基准。`scripts/selftest.py` 会检查「每个款式都必须有 overrides 条目」——不是为了强制差异化，而是防止出现「名字不同、结构一样」这种假推荐。
