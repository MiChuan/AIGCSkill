# 案例：男女两版同款证件写真

两套 spec 是同一个模板的两份实例：

- `specs/male-glasses.json` — 男生，锁本人五官，戴细金属框眼镜，蓝白条纹领带
- `specs/female-wave.json` — 女生，深棕大波浪，黑白条纹领带，小耳钉，主标题 KARINA

## 一、输入

用户原话（男生）：

> 男生：韩系学院风证件写真，年轻男生，保留原图五官样貌，精瘦脸型，下颌线清晰，
> 体脂率15%，利落短发，戴眼镜，干净淡感妆容，通透眼神，柔和氛围感，
> 身穿深色学院西装外套，藏青色V领针织背心，白色翻领衬衫，蓝白条纹领带，
> 浅灰蓝蓝色磨砂背景，人像居中，高清质感，胶片肖像，柔和柔光，
> 画面底部有文字排版，英文小字，照片加浅淡白边框，干净高级，8k，写实人像

负面提示词已按原样并入 `negative_extra`，与默认表合并后 40 条。

## 二、这段需求里有三处必须处理

### 1. 「精瘦脸型 + 下颌线清晰 + 体脂率 15%」与「保留原图五官样貌」互斥

照字面写进提示词，模型会优先执行改形（几何操作有明显视觉目标），保脸直接失败。

处理：`subject.face.shape` **保留原话**，由脚本的 `FACE_REWRITES` 翻译成：

> 脸型与参考图一致（不改骨相），用光让轮廓显出来，下颌线要靠光勾出来（形不变，只是被照亮），
> 皮肤紧致、面部干净无赘肉感（不改变原有脸型）。

后面再补一段可执行的光位：

> 下颌与颈部的交界用一个柔和但方向明确的明暗过渡分开，受光侧的下颌边缘保留一道细亮线，
> 阴影侧不补光。**不允许拉伸、收窄或重塑脸型**——脸型一旦被改，这张图就不再是这个人。

`meta.issues` 里会留一条 `I502`，记下被替换的原词，方便回溯。

### 2. 「照片加浅淡白边框」不能交给模型

模型画框的宽度在 1%–12% 之间随机跳，四边还常不等宽，有时还会在框外加一圈灰相纸。
提示词里改成：

> **不要在画面里画任何边框、白边、相纸、内阴影、投影或拼贴效果**，把整幅画面画满。
> 但构图时四周留出约 3% 的安全边。

边框由 `finalize.py --border 0.015` 加：3:4 的 8K 是 5760 宽，1.5% 短边 = 86px。

### 3. 「英文小字」是路线决策点

男生版给了主标题 `THE ACADEMY`（11 字符）+ 副标题 `PORTRAIT STUDY NO.02`（20 字符），在模型能力内 → `route=model`。

女生版是 `KARINA` + `STILL CHASING THE LIGHT` + `PORTRAIT VER.02`，也走 `model`。

如果用户给的是真实歌词（长句、多行），会自动切到 `overlay`——不是保守，是长句在 1.1% 字号下几乎必错。

## 三、成品提示词长什么样

跑：

```bash
python scripts/build_id_prompt.py --spec specs/male-glasses.json --outdir out/male
```

输出 3425 字符、13 节。节标题依次是：

```
【任务】【身份锁定｜最高优先级】【脸与妆】【发型】【服装｜逐件固定，不许自由发挥】
【姿态与构图】【背景】【光线】【影调与色彩】【画面底部文字排版】
【画面边缘】【画质】【禁止项】
```

几段的实际写法（可直接对照）：

**背景**

> 【背景】浅灰蓝色（约 #C7D0DA），无缝纸的磨砂面，有极细的哑光颗粒，完全无反光、无褶皱。
> 明暗：中心比四周亮约 10%，过渡极缓，看不出边界。背景必须是有距离感的：人物轮廓边缘
> 有一点点因为景深产生的柔化……背景上不允许出现任何图案、纹理、logo、光影道具、
> 窗帘褶皱或墙面接缝。不加暗角。

**光线**

> 光源面积很大（相当于 120cm 柔光箱贴得很近），所以阴影的边缘是宽的、软的，没有一道硬边。
> ……眼睛里有明确的眼神光：一块方形或圆形的柔光斑，位置一致、大小相同——
> 眼神光不对，脸再准也像假人。

**影调**

> 高调（high-key）影调，白位接近纯白但不过曝，黑位抬到 8–18 之间——暗部是「深灰」不是「死黑」。
> ……肤色是这张图最不能出错的地方：皮肤保持中性偏粉的暖调，明度高于背景一档，
> 饱和度低于背景里任何一块颜色（肤色一艳，人就假）。

## 四、出图参数

```json
{
  "image1": "<参考图绝对路径>",
  "input_fidelity": "high",
  "revise": false,
  "footnote": "<不传>",
  "quality": "high",
  "size": "1536x2048",
  "output_dir": "out/male/raw"
}
```

`revise=false` 在这个 skill 里比在场景图里更关键：一旦被改写，"不要画框"和保脸条款会被模型自己删掉，
出来就是一张带框、脸也变了的图。

## 五、收尾

```bash
# 水印 + 8K + 白边框
python scripts/finalize.py out/male/raw/x.png --out out/male/x_8k.jpg --target 8k --border 0.015

# 叠字（route=overlay 时才需要；本例是 model，跳过）
python scripts/settype.py out/male/x_8k.jpg --out out/male/x_final.jpg --spec specs/male-glasses.json
```

`finalize.py` 尾部 JSON 的关键字段：

```json
{
  "in_size": [1536, 2048],
  "out_size": [5760, 7680],
  "watermark": { "detect": { "score": 0.43, "aspect": 1.6 }, "applied": true,
                 "method": "edge-bilinear" },
  "border": { "applied": true, "px": 86, "mode": "inside",
              "hairline": "#E6E6E6",
              "verify": { "expected_px": 86,
                          "measured_px": {"left": 86, "right": 86, "top": 86, "bottom": 86},
                          "even": true } }
}
```

`measured_px` 四个数相等才算边框合格。这一项是量出来的，不是算出来的。

## 七、失败复盘：四个真实踩过的坑

### 坑一：水印压在人物边缘上，修完出现深色方补丁

合成图里水印正好横跨"西装 → 背景"的交界。

第一版修复用"左侧一列填充整个框"，框右半边的背景（亮度 200）被填成了西装色（30），
成图右下角是一块突兀的深色方块。

第二版改成逐列判断锚点，但把"双侧插值"和"单侧锚点"平均了——背景 200 和西装 30 平均成 115，
变成一条半深的竖带。

第三版：**两侧都可信才平均，否则优先用双侧插值的那一侧**。背景恢复 200，西装保持 30，
交界处变成一条连续的竖线（原本是斜线，被"推直"了，但颜色正确、没有台阶）。

教训：插值修补的颜色对错和形状对错是两件事。先保证颜色，形状退让是可以接受的。

### 坑二：用标准差判断"水印修掉了"，把自己逼着改正确的算法

修复后那块区域的标准差只从 80 降到 40，看起来"等于没修"。

但实际上文字的笔画已经全部消失，剩下的 40 是"西装 vs 背景"的真实对比——它本来就该在那儿。

换成**边缘能量**（`FIND_EDGES` 后的均值）做指标，44.3 → 12.9，一眼就看出修干净了。

教训：验收指标要对着"要消除的那个东西"设计，不是对着"这块区域"设计。

### 坑三：羽化带一宽就把水印留下来了

为了让修复区和原生区过渡自然，把羽化带宽从短边的 1/8 提到 1/4。

结果水印框高 29px、水印高 22px，羽化带 7px × 2 之后中心只剩 15px 被真正替换，
水印的上下边缘原样留下，边缘能量只降到 22（降 50%，不达标）。

教训：羽化带的宽度上限由**水印高度**决定，不是由画面尺寸决定。修复框通常只比水印大几像素，
没有给羽化留空间。

### 坑四：每个车道直接取一个像素，出来是竖条纹

最初按列取 `src[xx, top_coord]` 当锚点。相邻列的颜色有 2–4 级的随机差（颗粒），
插值后整块变成一排竖条纹，在 8K 上像印刷网纹——比原来的水印更显眼。

改成：先算每条车道的**平均颜色**，再沿车道方向做 9 像素的移动平均，然后插值。
移动平均吃掉的只是列间的随机差，衣服与背景的边界（几十级的跳变）还在。

## 八、已知局限（如实说）

水印如果**压在人物边缘上**，修复区与周围仍会有 5–8 级的亮度差，在 8K 上看是一条很淡的横带。

原因是插值的锚点离目标有 8px 的距离，而锚带的代表色是 9px 邻域的均值——两者都不可能完全等于
目标位置的真实值。渐变斜率越大、边界越硬，这个差越明显。

真实照片比合成图轻：磨砂背景本身有 2–4 级的颗粒，5 级差会被颗粒"藏"起来。
如果确实在意，两条路：

1. 出图时让右下角保持干净的背景（构图上前景别顶到角落），水印就落在纯色区，修复几乎无损
2. 用 `--watermark box:x,y,w,h` 把框缩到刚好包住文字，减少需要修补的面积

**不建议**为了避免这个差而扩大修复区——面积越大，插值假得越明显。


## 八、如果换成真人照片

三件事要重做：

1. **参考图**：按 `face-lock.md` 的清单挑一张正面平光的。侧脸或逆光会让保脸直接崩。
2. **文字路线**：真人版通常要排真实姓名或作品名，含英文人名的走 `model`，含中文的走 `overlay`。
3. **水印检测**：真人照片的背景如果有渐变、有影棚布纹，检测分数会偏高，可能误报。
   先跑一次 `--watermark auto` 看 `score`，> 0.3 但 `aspect` < 1.6 的通常是衣服边缘，不是水印。
   拿不准就先用 `--watermark off` 出一版，肉眼确认有没有水印再决定。
