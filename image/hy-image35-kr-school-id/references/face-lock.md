# 保脸：条件生成能做什么、不能做什么

## 一、机制先说清楚

Hy Image3.5 的参考图是**条件生成**，不是人脸 ID 注入（不像 IP-Adapter / InstantID 那种把人脸编码进隐空间的做法）。

区别体现在：

- 它会把参考图当作"这张脸长什么样"的视觉上下文，而不是"这就是这个人"的身份令牌。
- 所以**参考图的质量、角度、光线、遮挡，直接决定保脸精度**。参考图是正面平光、脸占比大的，保脸很稳；参考图是侧脸、逆光、戴墨镜的，模型就得猜。
- 也因此，**同名同姓的"换脸"是做不到的**。想做真正的人脸替换，得另外一套方案（不是这个 skill 的范围）。

参数上只有三个开关起作用：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `image1` | 参考图 | 身份来源 |
| `input_fidelity` | `high` | 图生图贴近原图的程度，保脸第一开关 |
| `revise` | `false` | **必须关**。开着会把提示词交给模型改写，保脸条款和"不要画框"会被删掉 |

## 二、证件写真比场景图好保，但也有新的难处

**好的一面**：脸在画面里的占比大（胸像构图，脸约占画面高度的 25–30%，而电影场景图通常只有 8%），模型有足够像素去还原五官。

**难的一面**：正因为脸大，任何一点漂移都会被放大。场景图里"差一点"的鼻子在 8K 证件照上就是"不是这个人"。

另外，证件照的常见要求本身就在和"不改五官"作对：

| 用户要的 | 实际发生的事 |
| --- | --- |
| 精瘦脸型 / 下颌线清晰 / 体脂 15% | 模型改骨相 → 换人 |
| 戴眼镜 | 眼睛前面多一层遮挡 → 瞳孔、双眼皮、眼裂两端信息丢失 |
| 干净淡感妆容 | 模型往"无瑕"走 → 磨皮 → 皮肤纹理消失，人也跟着变样 |
| 通透眼神 | 眼神光位置不对 → 像假人 |

所以这个 skill 的核心不是"如何写保脸条款"，而是**如何把互相冲突的要求拆开，各归各位**。

## 三、三条硬规则

### 规则一：改形词一律翻译成打光方案

见 `prompt-formula.md` 第三节。一句话：**摄影里让人显瘦的是侧光和阴影，不是改形**。

翻成光学表述后，模型既满足了"腿部轮廓清晰"的观感，又没有动骨相。观众看到的是清晰的下颌，不是另一张脸。

### 规则二：肤色必须单独立条款

肤色漂移是保脸失败最常见的表现，而且比骨相漂移更难察觉——你不会觉得"这人不像"，只会觉得"哪里怪"。

写清三件事：

- **色相**：中性偏粉的暖调，不许推成橘黄
- **明度**：比背景亮一档（高调片的关键）
- **饱和度**：低于画面里任何一块颜色（肤色一艳，人就假）

装配器会检查"有参考图但提示词里没有'肤色'二字"，命中报 `E509`。

### 规则三：眼镜要单独谈条件

参考图里的人不戴眼镜、生成时要求戴 → 等于在眼睛前面压一层半透明遮挡。模型的注意力被分去画镜框和镜片反光，眼睛的细节就丢。

如果眼镜是这个人固定的人设（比如用户就要"戴眼镜的男生"），**直接用一张戴眼镜的照片当参考图**。这比任何提示词技巧都有效。这条对应 `W506`。

生成时的额外约束（已写进第 3 节）：

> 镜框不能挡住眼睛的关键信息：瞳孔、双眼皮、眼裂两端都要透过镜片看清；镜片不反白、不反射屏幕、不出现第二重影子。

## 四、参考图准备清单

给用户的话可以照抄：

- **正面或轻微侧脸**（偏转 < 15°），能看清两只眼睛
- **平光或无强烈阴影**，脸上没有大面积高光或死黑
- **不戴墨镜、不被头发遮住眉眼、不戴口罩**
- **分辨率够**：人脸区域至少 400×400 像素
- **表情自然**：不要大笑（笑会改变眼型和法令纹，生成时也会延续）
- **背景干净更好**，但不强求——参考图只提供身份，背景会被完全替换

## 五、失败排查表

按"最可能的原因"排序，从上往下试。

| 现象 | 最可能的原因 | 怎么改 |
| --- | --- | --- |
| 完全不像 | 参考图侧脸 / 逆光 / 遮挡 | 换一张正面平光的 |
| 像"同类型的另一个人" | `input_fidelity` 没给 `high`，或 `revise` 开着 | 两个参数都改回来 |
| 脸被削瘦、下巴变尖 | 提示词里有改形词 | 查 `meta.issues` 里的 `E504`；只把改形词写在 `subject.face.shape` |
| 变年轻 / 变老 | 提示词里写了年龄感 | 删掉 `age_look`，或改成"与参考图同龄" |
| 皮肤像塑料 | 提示词里有"磨皮/无瑕/零毛孔"，或模型自己往美颜走 | 加"毛孔、绒毛、极淡的肤色不均"到第 3 节；负面加"塑料皮肤" |
| 眼睛不像 | 被眼镜挡住、或脸占比太小 | 换参考图；或把 `framing` 从"胸像"改成"头肩" |
| 表情变甜 / 变严肃 | 提示词里的表情描述和参考图差太远 | 表情写得越具体越好："嘴角非常轻微地提一下，闭嘴，牙齿不露" |
| 发色变了 | 没写 `hair.keep` | 写"发色必须是深棕，不能变成纯黑、不能变成黄棕或红棕" |
| 整体像另一个人种的骨相 | 参考图和描述冲突 | 描述里的"脸型"只能写光学方案，不能写形状 |

## 六、脸占比：一个容易被忽略的量化指标

保脸精度和脸部像素数直接相关。经验值：

| 构图 | 脸高 / 画面高 | 2K 出图时脸高 | 保脸表现 |
| --- | --- | --- | --- |
| 全身 | 6–10% | 120–200px | 只保得住"气质"，认不出是谁 |
| 半身 | 15–20% | 300–400px | 大致能认，细节会漂 |
| 胸像 | 25–30% | 500–600px | 稳，可用于交付 |
| 头肩 | 35–45% | 700–900px | 最稳，但制服信息少了 |

证件写真的默认构图是**胸像**（头顶到胸口），脸高约 27%。这个位置是"脸够大"和"制服看得见"的平衡点。要更保脸就往"头肩"走，代价是领带和 V 领只能看到一部分。

## 七、一句话总结

条件生成的保脸，本质是**减少模型需要"猜"的地方**：

- 脸长什么样 → 参考图说了算，提示词只负责"不许改"
- 怎么显瘦 → 光说了算
- 哪里必须有细节 → 提示词逐项点名（瞳孔、双眼皮、眼裂两端、发际线绒毛）

剩下的（服装、背景、边框、版式）全部交给确定性的东西：结构化文本和像素计算。
