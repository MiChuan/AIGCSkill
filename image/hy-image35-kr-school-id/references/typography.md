# 底部排版与白边框：把"手感"换成像素

这张照片的"高级感"，一半来自脸，一半来自两个几乎没人会注意的细节：**一行宽字距的小字**和**一圈等宽的白边**。

这两样恰好都是模型最不擅长的——因为它们要求的是**全局一致性**（三行字号关系、四边像素相等），而模型擅长的是局部合理性。

## 一、小字为什么会崩

图像模型没有字形表。它生成"STILL CHASING THE LIGHT"时，是在画一串"看起来像英文单词"的形状。字号越小，可用的像素越少，形状的容错就越低。

按画面高度统计的失败率（实测经验值，非严格统计）：

| 字号（占画面高） | 2K 图上 | 典型结果 |
| --- | --- | --- |
| > 4% | > 80px | 基本正确，偶尔字距不匀 |
| 2–4% | 40–80px | 多数正确，常见 1 个字母走形 |
| 1.2–2% | 24–40px | 大概率有错：漏字母、粘连、自造单词 |
| < 1.2% | < 24px | 几乎必错，且会画成"似是而非的字母串" |

固定机位、固定光照、固定服装的证件写真，文字的容错尤其低——因为画面里没有任何别的元素能"解释"这串字母，观众会直接盯着它读。

其他常见崩法：

- **字距自证清白**：模型会用"插入空格"来假装宽字距，结果词间距忽大忽小
- **基线漂移**：三行的基线不平行，2K 上差 2px，8K 上就是 8px
- **自行增删**：多一个 "S"、少一个 "E"，或者把 "THE" 和 "ACADEMY" 连成 "THEACADEMY"
- **字号关系错乱**：主标题和副标题一样大，或者副标题比主标题还大

## 二、两条路线

### 路线 A：让模型直接写（`route=model`）

**适用**：主标题 ≤ 24 字符、副标题 ≤ 46、页脚 ≤ 46，且全英文。

即使在这个范围内，也要在提示词里把"排版规则"单独写成一条清单——因为**规则比内容更容易画错**：

```
· 所有文字左对齐或居中对齐，只能选一种，每一行共用同一条对齐基准线；
· 字号只有三档，同档字号必须完全一致，不允许逐行随意缩放；
· 字距必须是均匀加宽的宽字距排法，不是把字母拉开填空隙；
· 字体只有一套，全部用细衬线体（类似 Didot / Bodoni 的现代衬线）；
· 文字是纯白或接近纯白，不描边、不发光、不加投影、不加色块底；
· 拼写必须逐字正确，字母数量与给定字符串完全一致。
```

最后还要加一句**逃生条款**：

> 如果无法准确排出一行文字，宁可不写，也不要用似是而非的字母凑数。

这句的作用是让"写错"和"不写"之间，模型选择后者。不写还能后期补，写错了会把整张图废掉。

### 路线 B：后期叠字（`route=overlay`）

**适用**：超长、含中文、或必须 100% 正确。

提示词里把文字段整段删掉，换成：

> 画面最下方 6–18% 是一条干净的留白带（背景延续，没有人物、没有衣领、没有阴影）。
> **这一段不要写任何文字、数字、符号、线条或装饰**——所有排版由后期叠加。

然后 `settype.py` 按数字排版。

### 决策阈值在装配器里

`build_id_prompt.py` 的 `TEXT_LIMITS` + 中文检测会自动选路线，并在 `meta.route_text` 里给出结果。判据是"模型的成功率"而不是"用户想要什么"——用户想要模型直接写的时候，恰恰是最容易出废图的时候。

## 三、字距：高级感的真正来源

同一句话、同一个字体，字距从 0 调到 +25%，观感会从"PPT 标题"变成"画册扉页"。这不是玄学：

- 常规正文的字距是**为阅读连续性**优化的，字与字挨得紧
- 展示型排版（书名、海报、刊头）的字距是**为形状节奏**优化的，每个字母都被当成一个独立的图形

这类写真底部的小字，几乎全部属于后者。所以：

| 行 | 字号（占画面高） | 字距（占字号） |
| --- | --- | --- |
| 主标题 | 3.0% | 14% |
| 副标题 | 1.1% | 26% |
| 页脚 | 0.9% | 22% |

**字号越小，字距要越宽**——因为小字的字腔本来就小，不加宽就会糊成一串。

Pillow 没有 letter-spacing 参数，所以 `settype.py` 是**逐字符绘制**的：

```python
cx = x
for ch in text:
    draw.text((cx, baseline), ch, font=font, fill=fill, anchor="ls")
    cx += font.getlength(ch) + track
```

两个细节：

- `anchor="ls"` 是"左基线"锚点。用 top 锚点的话，大小写混排时基线会跳（大写和小写的 top 不同）。
- 总宽度 `= Σ getlength(ch) + track × (n-1)`，不是 `track × n`——最后不加尾巴，否则居中会偏半个字距。

## 四、字号换算

以画面高度为基准，不按宽度。因为竖版的宽度变化大，高度相对稳定。

| 画面高 | 主标题 3% | 副标题 1.1% | 页脚 0.9% |
| --- | --- | --- | --- |
| 2048（2K 原生） | 61px | 23px | 18px |
| 3840（4K） | 115px | 42px | 35px |
| 7680（8K） | 230px | 84px | 69px |

8K 上主标题 230px、字距 32px，观感是"小而清楚"——这正是韩国证件写真的样子：字不大，但每一笔都锐利。

## 五、位置：靠底，但不贴边

`choose_band()` 的逻辑和一般做法不同：**不去找全图最安静的横带**，而是从底部往上试，第一块"没有大面积高光"的就用。

理由：找最安静的带子会把文字排到画面中部（衣服纹理最少的地方往往是胸口以上的背景），而证件写真的文字**必须在下三分之一**。位置是设计的一部分，不是优化出来的结果。

判据只有一个：带子里接近纯白（> 245）的像素不能超过 12%。超过就说明那块地方有白衬衫、白领子或白边框，白字会糊进去。

垂直定位：文字块在带内**居中**；块比带子高时贴底排，但绝不越过画面高度的 55%。

## 六、字色与对比度

自动选：

- 带子平均亮度 > 140 → 深灰 `#262A30`
- 否则 → 近白 `#F8F8F6`

然后算 WCAG 对比度，低于 3:1 报警。3:1 不是随口定的——它是"大字号文本"的最低可读阈值（WCAG AA 对大字的定义是 18pt 以上或 14pt 粗体以上）。证件写真底部的小字在手机上经常被缩到 1/4 显示，低于这个值就直接糊成一片灰。

透明度默认 0.94 而不是 1.0：让文字和背景之间保留一点点渗透，看起来是"印在纸上"而不是"贴在上面"。

## 七、白边框：绝对不能交给模型

模型画框的失败模式极其稳定：

| 失败 | 表现 |
| --- | --- |
| 宽度随机 | 1%–12% 之间跳，同一批图里每张都不一样 |
| 四边不等宽 | 上下 40px、左右 65px 这种 |
| 多一层相纸 | 框外再来一圈灰，像贴在一张卡纸上 |
| 框内投影 | 白框内侧加一圈内阴影，看起来像相框 |
| 框被画进画面 | 主体被压缩到框内，比例全变 |

而"1.5% 白边"在视觉上恰恰是靠那 2 个像素的精度撑起来的：差 20px 就不像相纸，像 PPT 的边框线。

所以：

- **提示词里明确禁止**：「不要在画面里画任何边框、白边、相纸、内阴影、投影或拼贴效果」，同时要求"四周留出约 3% 的安全边"
- **边框由 `finalize.py` 按像素画**，两种模式：

| 模式 | 行为 | 总尺寸 | 适用 |
| --- | --- | --- | --- |
| `inside`（默认） | 框画在画面内部 | 不变 | 比例必须严格保持（交付尺寸固定） |
| `outside` | 框加在外部，内图先缩到 `size - 2×px` | 等于 `--size` | 要"照片放在相纸上"的观感 |

`inside` 会盖掉最外圈 1.5% 的画面——这正是提示词要求"四周留 3% 安全边"的原因，逻辑闭环。

`--border` 的取值规则：**小于 1 视为相对短边的比例，≥ 1 视为像素**。所以 `--border 0.015` 是 1.5%，`--border 86` 是 86 像素。

### 发丝线

白边框和纯白衬衫相邻时，边界会"粘"在一起。`add_border()` 会先量画面最外圈的亮度，如果是浅色（> 226），就在框的内侧画一条 `#E6E6E6` 的发丝线（宽 = 边框宽 / 45）。

这条线不是装饰，是**让白边看起来是"另一样东西"**。没有它，白边框在浅灰蓝背景上就是一条模糊的渐变。

### 自检

`border.verify.measured_px` 是加完框后**从成图上量回来的四边宽度**（从四条边向内数连续等于框色的像素）。四个数必须相等——白框和白衬衫相邻时，肉眼根本看不出 2px 的偏差，但把图放进 ID 模板里对齐时，那 2px 会让整张脸偏。

## 八、执行顺序

```
trim（裁掉模型自画的框）
  → 水印（补片）
  → 重采样（→ 8K）
  → 白边框（按 8K 尺寸算像素）
  → 叠字（按 8K 尺寸算字号）
```

每一步的位置都有理由：

- 水印在边框之前：水印可能落在要被白边盖住的那一圈上
- 边框在重采样之后：边框宽度按交付尺寸算，先加框再放大会让框跟着放大 4 倍，边缘还多一圈插值糊边
- 叠字在边框之后：文字要知道边框在哪，才能躲开它（`detect_bottom_bar()` 自动识别）

## 九、已知局限

- **中文字**：`overlay` 用的是系统字体（默认 Georgia，中文需另指 `--font`）。字距算法按字符计，中英混排的字距比例需要手动调 `--scale`。
- **模型已经写了字**：`route=model` 出的图如果字写错了，不能局部修——字形和周围的像素是连在一起的，贴一个字补丁会比错字更显眼。重出一张（换随机种子比换措辞有效），或者改用 `overlay` 重做。
- **底部是强纹理**（比如大格纹西装）：文字带方差会很高，`settype.py` 会报警。这时候要么缩小 `--zone`，要么出图时把构图往下留白一点。
- **边框色不是纯白**（比如暖白 `#FDFCF8`）：记得同时检查 `--hairline`，发丝线在暖白边上会偏冷。
