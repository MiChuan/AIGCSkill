# 纪实调色的量化口径

> 「浓郁」「通透」「立体」「干净」这四个词，眼睛的判定阈值非常不稳定：
> 同一张图在手机屏上叫通透，在显示器上叫发灰。
> 这份文档把它们翻译成六个可测量的量，`scripts/grade.py --check` 输出的就是这六行。

## 一、为什么要量化

因为「调过头」和「刚刚好」在同一条轴上，只差几个数：

| 观感 | 实际发生的事 | 可测量的量 |
| --- | --- | --- |
| 通透 | 高光没被裁，暗部没被压，中间调有斜率 | `p5` / `p99` / `contrast_p90_p10` |
| 浓郁 | 同色相内的纯度提高，明度不变或略降 | `sat_mean` + 色相不漂 |
| 虚假 | 饱和度靠提亮实现，色相向橙/青两端分离 | `sat_mean` 高 + `p99` 顶到 255 + 色相漂移 |
| 干净 | 暗部有结构没有噪点块 | `shadow_open` / `shadow_luma` |
| 立体 | 大半径局部对比，而不是小半径锐化 | 无法直接测，靠看边缘光晕 |

一句话：**「虚假感」在数值上几乎总是等于「高光被裁 + 饱和靠提亮 + 色相漂移」这三件事同时发生。**

## 二、六个轴

### 1. 动态范围：`contrast_p90_p10`

P90 与 P10 的亮度差，单位是 0–255 的级数。

- 纪实摄影的合理区间：**95–205**
- 低于 95：色阶没铺满，画面发灰发平——这是「滤镜感」的第一特征，常见于隔着车窗拍的、压过高光的、加了灰雾的
- 高于 205：中段被拉得太开，暗部或高光必有一端在牺牲

这个量只描述**中段的跨度**，不描述端点，所以必须和下面两项一起看。

### 2. 端点：`p5` / `p99`

- `p5` 落在 **3–32**：黑位既没有压死（=0）也没有被提到发灰（>40）
- `p99` 落在 **230–254**：白位有亮部但没有一路裁到 255

为什么不是「越黑越好、越白越好」：
黑位压到 0 的图，暗部就是一块没有信息的黑；白位到 255 的图，云和雪就是一块没有层次的白。
纪实摄影的容错度高，恰恰是**两端都留了余量**——这是它「耐看」的技术原因。

### 3. 暗部开度：`shadow_open` / `shadow_luma`

做法：把画面切成约 30×30 的小块，按平均亮度排序，取**最暗的 20%**，
算这些块内部的明度标准差。

- `shadow_open` ≥ 5：最暗的区域内部还有结构（地形、衣褶、墙面、树影）
- `shadow_open` < 5：最暗的区域是一块平地，也就是「死了」
- `shadow_luma` 落在 4–92：最暗的区域亮度合理。**高于 92 说明暗部被整体提亮成雾**——这是假 HDR 的典型病征，比暗部压死更常见

不用固定阈值挑「暗块」是有原因的：整幅都是亮调的画面（雪原、沙滩）里根本没有绝对的暗块，
用固定阈值会一个都选不出来，最后报 `skip`。按分位取，任何图都能得到一个有意义的读数。

### 4. 饱和度：`sat_mean`

在 20 < 亮度 < 235 的像素上，取 HSV 的 S 均值（排除纯黑纯白，避免把天空的过曝白算成零饱和）。

- 合理区间：**0.26–0.56**
- 低于 0.26：色相出不来，草是灰绿、天是灰蓝
- 高于 0.56：色块之间开始糊成一片，相邻色分不开

这个区间很宽，因为**均值本身不是判据**。真正的判据是：拿掉均值之后，色块内部还有没有层次。
一张饱和度 0.50 但每块颜色内部有深浅变化的图，比一张饱和度 0.40 但整片纯色的图更「浓郁」。

### 5. 色相锚点：`hue_sky` / `hue_green` / `hue_earth`

在饱和像素里按色相分段，算环形均值。

| 元素 | 期望色相 | 偏出的典型症状 |
| --- | --- | --- |
| 天空 | 195°–228° | <195 偏青绿（像阴天）；>228 偏紫（像加了品红） |
| 植被 | 68°–148° | <68 偏黄（秋天是对的，春天是错的）；>148 偏青（像冷调滤镜） |
| 大地 | 12°–50° | <12 偏洋红；>50 偏黄绿（土变草） |

色相是最不能碰的东西。**饱和度和明度可以大幅调整，色相偏移超过 8° 就会被人读成「滤镜」。**
这也是为什么本 skill 的所有参数里，只有饱和度和明度在被调，色相一律只做 ±3° 以内的微调。

### 6. 色偏：`cast_rg` / `cast_bg`（只作参考，**不给判定**）

这一项我刻意不做判定，原因值得写清楚，因为它是个反直觉的坑：

**任何基于「找出近中性像素」的色偏检测，都会被色偏本身骗。**

实测例子：给一张图整体加 +18 的蓝。

- 原本 S=0.29 的土路，加了蓝之后 B 抬高、R 不变，反而变得更接近中性，被选进「中性样本」
- 原本 S=0.15 的远山，加了蓝之后被推过阈值，被踢出样本
- 于是「中性样本」整个换了一批物体，读数从 +13 变成 −6，方向都反了

也试过白块法（取最亮的 1% 当白色参考）：天空亮的片子会把这个蓝天当成「白」，
一张完全正常的照片会被报出 +36 的蓝色偏。

结论：**没有灰卡或参考白，色偏在软件层面不可判。** 所以这一行只把数报出来，
旁边附一个 `cast_conf`（那批中性样本到底中不中性，>0.22 就说明样本本身就不中性）。
判色偏请看图，或者拍一张灰卡。

同理，`grade.py` 的自动白平衡**默认关闭**：在草地占三分之一的风景片里，
灰世界白平衡会把暖色的土路推成紫色。拍摄时白平衡已经对了的片子，再猜一次只会更差。

## 三、三套预设的差异

| 参数 | nature 风光 | street 扫街 | travel 旅行 |
| --- | --- | --- | --- |
| `shadow_lift` | 12 | 9 | 11 |
| `white_level` | 249 | 247 | 248 |
| `mid`（中段对比） | 1.18 | 1.24 | 1.20 |
| `vibrance` | 1.16 | 1.10 | 1.14 |
| `sat_sky` | 1.10 | 1.04 | 1.09 |
| `skin`（肤色保留） | 0.90 | 0.85 | 0.88 |
| `clarity` | 24 | 30 | 26 |
| `grain` | 0 | 0.06 | 0.04 |

读法：

- **风光**：饱和给足、颗粒给零、暗部抬得最多（草地的暗部最容易糊成一片黑绿）
- **扫街**：对比最硬、颗粒最多、**肤色保护最强**——街头片子一旦脸变橘，整张就废了
- **旅行**：两者之间，因为它同时包含风光与人

`neutral` 预设不做风格化，只做色阶归位和极轻的归正，用来 A/B 对比「调色到底动了什么」。

## 四、已知局限

1. **8bit 不是无限的。** 色阶跨度只有 45 级的图，强行拉到全幅必然出现断层。
   脚本把拉伸倍数限制在 2.5 倍，超过就在报告里标 `capped`——这种图从源头上就该重拍。
2. **HSV 往返有量化误差。** Pillow 的 HSV 是 8bit，色相量化为 1.4° 一格，来回转换一次
   有约 1 级的误差。对照片无影响，对纯色块素材可见。
3. **`sat_mean` 对画面内容极敏感。** 一张满幅红花特写和一个雪山远景，合理值差一倍以上。
   这个数只能同题材之间比较，不要跨题材套阈值。
4. **局部对比测不出来。** `clarity` 的效果是边缘的明暗过渡变陡，这在直方图上完全看不出来，
   只能看。所以它不能进体检，只能进视觉验收。
5. **这套口径是「数码彩色摄影」的口径。** 黑白、红外、多重曝光、胶片扫描都不适用。
