# 调色链：五道工序与它们的顺序

`scripts/grade.py` 做的事，本质上是一个摄影师在 Lightroom 里会做的事，
只是把顺序固定下来了——顺序错了，同样的参数会得到相反的结果。

```
白平衡（默认关） → 色阶归位 → 影调曲线 → 分色饱和度 → 局部对比 + 颗粒
```

## 一、色阶归位：最容易被跳过的一步

**为什么它必须排在影调曲线前面**

一张被压过色阶的图（假 HDR、网红滤镜、隔着车窗拍的、压过高光的），
它的色阶可能只占 117–162 这 45 级。

在这种图上加对比，只是在 45 级里加对比——灰还是灰，只是灰得更有层次。

必须先把它拉回 8–248，后面所有影调调整才有意义。

**算法**

```
lo, hi = P1, P99
if hi - lo >= 215: 跳过（已经铺满）
gain = min(2.5, 240 / (hi - lo))
LUT: y = (x - lo) * gain + 8
```

三个刻意的设计：

1. **用 P1/P99 而不是 P0/P255。** 端点常被一两个高光或噪点占住，用它俩当黑白场会拉偏。
2. **只拉伸，不压缩。** 跨度已经够大的图不动，避免把低反差的艺术处理（雾天、雪景）拉成硬调。
3. **上限 2.5 倍。** 跨度只有 45 级的图，理论上要 5 倍才能铺满，但 5 倍拉伸会把
   8bit 的量化台阶放大成肉眼可见的断层。超过 2.5 倍时报告里标 `capped: true`——
   这种图从源头上就该重拍，不该指望后期。

**拉完色阶的副作用：饱和度一起上去了。**

拉伸是线性的，但饱和度是相对量：`S = (max-min)/max`。同一个色差，在低亮度下的相对占比更高。
所以拉完色阶，画面会自然地更艳一档。这时候再按原参数加 vibrance，就是两道加法叠加。

脚本的处理是**按拉伸倍数反向补偿**：

```
k = 1 / gain^0.6
vibrance' = 1 + (vibrance - 1) * k
```

gain=1.6 时 k≈0.75，vibrance 1.14 变成 1.105。经验值，但方向是对的：
拉得越狠，饱和加成越要收回来。这条不做的话，输出的典型症状就是「浓郁」变成「廉价」。

## 二、影调曲线：三个窗口

单通道 LUT，四个参数，四步叠加：

```
y = x
y += (mid - 1) * (x - 0.5) * 4x(1-x)          # 中间调对比
y += lift * (1 - y)^3                          # 黑位抬升
if y > knee: y = knee + (y - knee) * (wp - knee) / (1 - knee)   # 白位压缩
y += vintage * (0.035x² - 0.012(1-x)²)         # 复古分离（仅 R 通道，B 反向）
```

关键是前两步的**窗口函数**：

- `4x(1-x)` 在 x=0 和 x=1 处为 0，在 x=0.5 处为 1。
  所以「加对比」这个动作在两端自然衰减为 0——**不会动黑，也不会动白**。
  这正是不用普通 S 曲线的原因：普通 S 曲线会把端点一起推出去。
- `(1-y)^3` 只在暗部有值，到中间调已经衰减到可以忽略。
  所以「抬黑位」不会把中灰一起提亮。

第三个窗口 `knee` 把 0.70 以上的亮度线性收进 `white_level`，
让 P98 落在 248 而不是 255。这是「高光通透」的可执行写法：
高光不是被压平，而是被**收窄到还有余量的位置**。

第四个是复古分离：R 通道在高光加、暗部减，B 通道反向。幅度是通道间差 1–3 级，
肉眼几乎看不出，但它会把「数码味」抹掉一层。这就是 `vintage` 参数，
0 是干净的数字感，0.35 是淡淡的胶片味，**超过 0.5 就开始像老照片滤镜了**。

## 三、分色饱和度：先剔掉肤色

HSV 空间里做三件事，只做一次 RGB↔HSV 往返（8K 图往返三次会慢三倍）。

**1. vibrance 而不是 saturation**

```
s' = s + (gain - 1) * s * (1 - s) * 2
```

中间饱和度的像素提得多，已经很艳的提得少。这条曲线的形状就是 vibrance 与 saturation 的区别：
saturation 是整体乘法（`s' = s * gain`），会把已经接近 1 的色块直接推到溢出。

**2. 按色相分带加权**

天空 196°–224°、植被 72°–148°、大地 14°–46°，各给一个独立增益。
掩膜带 7° 羽化，避免色相在边界处跳变。

**3. 肤色排除法（这一步最容易做错）**

土墙、岩石、皮肤在色相上几乎重叠：大地 14°–46°，肤色 12°–42°。
所以「先给大地加饱和，再给皮肤减一点」这种做法一定会让脸跟着走。

正确做法是**先把肤色区域从分色掩膜里减掉**（`not_skin = invert(skin_mask)`），
再让肤色按比例回到它原始的饱和度：

```
s = composite(s_original, s_graded, skin_mask * protect)
```

`protect = 0.88` 的意思是「肤色保留 88% 的原饱和度，另外 12% 跟着全局走」。
这样脸既不会变成橘色，也不会在整体偏冷的画面里显得像贴上去的。

肤色的掩膜条件是三重交集：色相 12°–42°、饱和 < 0.59、明度 76–236。
宽松是有意的——宁可多保护一点，也不要漏掉受光面。

## 四、局部对比：半径决定它是「立体」还是「锐化」

```
radius = max(3.0, 长边 / 620)
UnsharpMask(radius, percent=clarity, threshold=3)
```

只作用在 V 通道（明度），不动色相与饱和度，所以不会产生彩色边缘。

半径是这里唯一的玄机：

| 半径 | 效果 | 用途 |
| --- | --- | --- |
| 1–2 px | 锐化：边缘变脆，出现白边 | 输出前的最后一道，不是这里 |
| 长边/620（约 12px @8K） | 局部对比：光影的过渡变陡 | **这里要的** |
| 长边/40（约 190px @8K） | 更大的结构对比，接近 clarity 滑块拉满 | 容易出光晕，慎用 |

纪实摄影的「立体」来自光线本身有方向。局部对比只是把已有的明暗关系**说得更清楚**，
不是无中生有。所以 `percent` 上限压在 30 左右——再高就开始有「HDR 味」了。

## 五、颗粒：换算，不是拍脑袋

`Image.effect_noise(size, sigma=64)` 生成的是标准差 64 的高斯噪声。
要得到「标准差 = amount × 40 级」的颗粒，映射系数必须是 `amount × 40 / 64`：

```
factor = amount * 40 / 64
noise_lut: (i - 128) * factor + 128
v = add(v, noise_patched, 1.0, offset=-128)
```

`offset=-128` 把噪声的直流分量减掉，所以只加波动、不加亮度。

`amount` 的参考值：0.04 是几乎看不见的底片感，0.06 是明显但干净的颗粒，
**超过 0.15 就开始在暗部糊成噪点**，与本风格「暗部细节丰富」的核心诉求直接冲突（`W307`）。

只加在 V 通道，不加在色度上——彩色噪点是数码噪声的特征，不是胶片的。

## 七、已知局限

1. **顺序不能换。** 色阶归位必须在影调曲线之前，否则对比是在被压缩的区间里加的。
   分色必须在色调之后，否则色相锚点会跟着曲线漂。
2. **8bit 的色相是 1.4° 一格。** HSV 往返一次有约 1 级误差，纯色块素材上可见。
3. **拉伸倍数有上限（2.5×）。** 超过就断层，报告里会标 `capped`。
4. **自动白平衡默认关闭。** 原因见 `color-science.md`：草地会让灰世界把土路推成紫色。
5. **不能救回被裁掉的信息。** 高光已经 255 的地方，任何曲线都是纯白；
   暗部已经 0 的地方，抬黑位只会抬出一片均匀的灰，不是细节。
6. **不做局部蒙版。** 整幅统一处理。需要「只给天空压暗」这类操作，得回到 Lightroom。
