# 提示词结构：三档产物怎么用

`build_prompt.py` 同一份 spec 出三档产物，差别在「塞在哪儿用」和「允许抄多少原文」。
不是越靠右越好——anchored 最像也最容易把模型带成背诵器，按场景选。

## 三档对照

| 档 | 文件 | 用途 | 是否带原文句子 |
| --- | --- | --- | --- |
| short | `prompt-short.txt` | 塞在 system prompt / 对话开头，≤ 200 字 | 不带 |
| standard | `prompt-standard.md` | 主用版本，七段式规格表 + 岔路 + 负向 + 自检 | 不带 |
| anchored | `prompt-anchored.md` | standard + 1–3 句语感锚句 | 带，最多 3 句 |

## short

只留骨架：角色 + 任务首句 + 3 条要求 + 5 个禁用词 + 1 条自检，强压在 200 字内。
用于 token 受限的场景——长上下文里要塞角色、任务、风格三件事，short 是风格这事的浓缩。

short 故意牺牲细节，只取 specs[:3]——不要期待它复刻得像，让它「方向对」就行。
要复刻得像就用 standard。

## standard

主用版本。七段式：

1. **角色** — 一句话身份，明确「按规格写作，不以个人风格覆盖给定规格」
2. **任务** — 写什么、写多长、给谁看
3. **风格规格** — 表格：# ｜ 轴 ｜ 要求 ｜ 原文证据 ｜ 怎么算过
4. **岔路选择** — 「当 X，用 A，不用 B」三栏表，把风格里最易走偏的几个路口钉死
5. **负向约束** — 禁用词 / 禁用结构 / 不写的内容
6. **交稿前自检** — 必勾项 + 量化目标表
7. （仅 anchored）**语感锚点** — 1–3 句原文照抄，标明「只学语感不抄句子」

**standard 不带任何原文句子**——这是底线。规格里的 evidence 字段是给写 spec 的人
看的（印证这条规格不是凭空编的），渲染时不进 standard 的正文，只进表格作为佐证。
模型实际执行时只看 rule 和 check。

## anchored

加了语感锚句的版本。锚句上限 3 句，单句不过 30 字，全部从原文照抄。用途是
让模型对齐「停顿 / 句式 / 用词层级」——比表格规格更直接，但也更危险。

**只学语感，不抄句子**——render 时强制打印这一行。让模型把锚句的内容换成新主题，
保留句式和停顿：

```
锚句: 3nm 是节点名。不是尺寸。
学法: X 是 Y。不是 Z。   <- 用这个句式写新主题
不学: 把 3nm / 节点名 / 尺寸 这些词搬到新文本
```

如果锚句开始让模型输出抄原文的句子，回到 standard。anchored 是高风险高收益，
不强制用。

## 不该混的用法

- ❌ 把 short 当主版本用——丢细节多，复刻分数会比 standard 低 10–15 分
- ❌ 把 anchored 直接发给没有任务说明的模型——锚句会盖过规格
- ❌ 三个档一起塞给模型——自相矛盾，模型会挑短的那个执行
- ❌ 修改 prompt-standard.md / prompt-anchored.md 后再喂模型——脚本是 source of truth，手改一次就和下一轮校验脱钩

## 三档之外

`prompt.json` 是规格本身（normalise 之后的 spec），不是给模型读的——
是给 `build_prompt.py --check` 用的、给回归测试用的、给人审稿用的。
**不要把 prompt.json 当作提示词发给模型**。要发就发 short / standard / anchored 三选一。
